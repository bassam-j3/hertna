# دليل شيفرة مشروع حارتنا (Thesis Codebase Guide)

هذا الدليل هو خريطة مرجعية سريعة لفهم هيكلية الأكواد في مشروع "حارتنا". صُمم هذا الدليل لمساعدتك كمهندس رئيسي (Lead Developer) في استعراض الكود بسرعة وثقة تامة أمام لجنة التحكيم.

---

## 1. نظرة عامة على المعمارية (Architecture Overview)
يعتمد مشروع "حارتنا" على معمارية العميل-الخادم (Client-Server Architecture) بأسلوب حديث ومفصل:
- **الواجهة الأمامية (Frontend):** مبنية باستخدام مكتبة React مع إطار Vite لضمان سرعة بناء فائقة. تم تطبيق نمط المكونات الدقيقة (Micro-components) لضمان أن كل واجهة أو زر له ملف منفصل خاص به (Single Responsibility Principle).
- **الخادم (Backend):** مبني باستخدام إطار عمل NestJS، وهو إطار يعتمد على معمارية الوحدات المستقلة (Modular Architecture). يتم استخدام Prisma كأداة (ORM) للاتصال بقاعدة بيانات آمنة ومرنة.

---

## 2. هيكلية الواجهات الأمامية (Frontend Directory Map - React)
توجد كافة ملفات الواجهة داخل مجلد `frontend/src/`. تعتمد الهيكلية على فصل واجهات المستخدم (Components) عن المنطق البرمجي (Hooks & Services).

```text
frontend/src/
├── components/          # المكونات المرئية وواجهات المستخدم
│   ├── layout/          # مكونات الهيكل الأساسي (شريط التنقل العلوي والسفلي)
│   ├── modals/          # النوافذ المنبثقة (Popups) مثل إضافة طلب
│   ├── admin/           # مكونات لوحة تحكم اللجنة (السرية)
│   ├── App.tsx          # الموجه الرئيسي (Router) ونقطة الانطلاق للتطبيق
│   ├── HomeFeed.tsx     # الصفحة الرئيسية التي تعرض المنشورات مرتبة حسب الموقع
│   ├── SearchView.tsx   # واجهة الخريطة التفاعلية للبحث الجغرافي
│   ├── ProfileView.tsx  # واجهة الملف الشخصي للمستخدم
│   └── AdminDashboardView.tsx # الواجهة الرئيسية الخاصة بلجنة الحي
├── contexts/            # السياق العام (Global State Management)
│   └── AuthContext.tsx  # يدير حالة تسجيل دخول المستخدم (Token) في كامل التطبيق
├── hooks/               # خطافات (Custom Hooks) لتنظيم المنطق البرمجي المعقد
│   └── useAdminData.ts  # خطاف لجلب بيانات المستخدمين والتذاكر للوحة الإدارة
├── services/            # دوال الاتصال بالخادم (API Fetchers)
│   ├── apiClient.ts     # ملف الإعداد الأساسي لطلبات الشبكة (Axios Interceptors)
│   ├── authService.ts   # طلبات تسجيل الدخول والتوثيق
│   └── itemService.ts   # طلبات جلب وإضافة المنشورات الجغرافية
└── types/               # تعريفات البيانات (TypeScript Interfaces) لضمان خلو الأكواد من الأخطاء
```

## 3. هيكلية الخادم الزبون (Backend Directory Map - NestJS)
تم تصميم الخادم بنظام الوحدات المستقلة (Modules) داخل مجلد `backend/src/` لتسهيل التوسع مستقبلاً.

```text
backend/src/
├── auth/                # وحدة التوثيق وإنشاء رموز الدخول (JWT Tokens)
├── users/               # وحدة إدارة بيانات المستخدمين والتسجيل
├── posts/               # وحدة المنشورات (احتياجات، إعارة، تبرع)
├── swaps/               # وحدة المبادلات وإدارة بروتوكول المصافحة (Handshake)
├── tickets/             # وحدة تذاكر الدعم الفني
├── admin/               # وحدة لوحة التحكم (المحمية بصلاحيات اللجنة)
└── prisma/              # وحدة الاتصال المباشر مع قاعدة البيانات
```

### الفرق بين Controller و Service:
لتطبيق أفضل الممارسات الأكاديمية (Separation of Concerns)، تم تقسيم كل وحدة إلى جزئين رئيسيين:
1. **المتحكم (Controller):** وظيفته فقط استقبال الطلب من الإنترنت (HTTP Request)، التحقق من صحته والمصادقة عليه (Route Guards)، ثم توجيهه. (بمثابة موظف الاستقبال).
2. **الخدمة (Service):** تحتوي على المنطق البرمجي العميق (Business Logic). تقوم بالاتصال بقاعدة البيانات (Prisma) لتنفيذ العمليات المطلوبة (إنشاء، حذف، حساب المسافات). (بمثابة الموظف المختص).

---

## 4. تدفق البيانات (Data Flow Example)
لنفترض أن المستخدم قام بتسجيل الدخول وطلب عرض المنشورات القريبة منه في الصفحة الرئيسية، هكذا تسير رحلة البيانات:

1. **الواجهة (React Component):** المكون `HomeFeed.tsx` يستخدم تقنية `Geolocation` لمعرفة موقع المستخدم ويطلب البيانات.
2. **الخدمة الأمامية (Frontend Service):** الدالة الموجودة في `itemService.ts` تمرر الإحداثيات وتستخدم `apiClient` لإرسال طلب HTTP آمن.
3. **متحكم الخادم (NestJS Controller):** ملف `posts.controller.ts` في الباك إند يستقبل الطلب ويتحقق من الـ Token.
4. **خدمة الخادم (NestJS Service):** ملف `posts.service.ts` يستلم الإحداثيات ويحسب المسافات بين المستخدم والطلبات في قاعدة البيانات.
5. **قاعدة البيانات (Prisma DB):** يتم استخراج الطلبات وتعود كاستجابة صالحة.
6. **العرض النهائي:** تصل البيانات إلى `HomeFeed.tsx` ويتم رسم بطاقات الطلبات على الشاشة أمام المستخدم!
